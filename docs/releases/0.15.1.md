# OMXTerm 0.15.1

Status: preparation and native verification in progress; not published.
Delivery: #397. Dead-key correction: #395 and PR #396.

## Changes

- Preserve dead-key literals completed with Space on native input paths that
  commit text without composition events, including Fedora KDE/XWayland.
  Apostrophe, double quote, grave and tilde are no longer replaced by an ASCII
  space. The browser's keyboard layout remains the text authority.
- Preserve the existing successive-Space workaround, native macOS Option input,
  terminal Alt/Control modifiers, held-key ownership and Kitty keyboard reporting.
  Pending native completion is cleared on text commit, cancellation or focus loss.

No configuration or theme schema migration is required. There are no intentional
incompatible changes, new settings or dependencies.

## Remaining risks and limitations

- The maintainer confirmed the dead-key fix on a separate Fedora development
  AppImage. Native Fedora input probes also matched the plain-text control for
  all seven exercised cases. These observations are not exact release-artifact
  verification or exhaustive keyboard-layout coverage.
- The general Fedora host fixture still times out waiting for complete ordered
  large DOM paste through the real PTY (#398). Its final keyboard regressions
  pass, but the Fedora suite is **not** claimed as fully passing. The timeout's
  relationship to production behavior remains unresolved; a baseline probe was
  inconclusive. It is not hidden by changing assertions or deadlines.
- Native event sources, physical GPUs and desktop environments beyond recorded
  automation remain **UNVERIFIED**. Existing-release owner dogfood on macOS,
  Ubuntu and Windows is not new-build verification.
- macOS has an ad-hoc integrity seal, no Developer ID signature and no
  notarization. Linux and Windows artifacts are unsigned. No package has a
  verified publisher identity or an independent security-audit guarantee.
- Linux requires X11/XWayland and retains its fixed `--no-sandbox` policy.
  `--appimage-extract-and-run` is the supported fallback when kernel-FUSE
  mounting is unavailable.
